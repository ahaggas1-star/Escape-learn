# سياق المشروع — PROJECT_CONTEXT

## 1. الغرض

هذه الوثيقة مرجع تأسيسي لفهم وبناء منصة رقمية موحّدة تجمع بين فكرتين:

1. **منصة رقمية أسرية تفاعلية** لتحويل القيم التربوية إلى أهداف ومهام وسلوكيات
   قابلة للتطبيق والمتابعة داخل الأسرة.
2. **برنامج قيمي تربوي طويل المدى** يهتم بغرس القيم لدى الأبناء عبر مراحل عمرية
   وأساليب تربوية متعددة.

**الهدف من الدمج:** بناء منصة واحدة تتيح لولي الأمر اختيار قيمة تربوية رئيسية، ثم
اختيار أهداف جاهزة أو إنشاء أهداف خاصة، ثم متابعة تحقيق هذه الأهداف مع الابن، مع
استخدام التلعيب (Gamification) كأداة تحفيز واستمرارية.

> هذه الوثيقة لا تمثل المواصفات النهائية الكاملة، لكنها تحدد الاتجاه: المنتج،
> والمنطق التربوي، وسير العمل، وحدود الـMVP، وطريقة التفكير التي يجب الالتزام بها.

## 2. قاعدة مهمة جدًا: منع الافتراضات

على أي منفّذ أو مطوّر أو مصمم أو نموذج ذكاء اصطناعي:

- **لا يجوز بناء قرارات جوهرية على افتراضات غير مؤكدة.**
- عند نقص معلومة تؤثر على توجّه المشروع، يجب الرجوع لصاحب المشروع بسؤال واضح ومحدد
  قبل اتخاذ القرار.

**القاعدة التنفيذية:**
- إذا كان القرار يؤثر على المنتج/المستخدم/الخصوصية/الاستثمار/المنهج التربوي → **اسأل أولًا**.
- إذا كان القرار تفصيلًا تقنيًا قابلًا للعكس → **نفّذه بشكل منظم ووثّقه** (مع `TODO`/`Placeholder`).

القرارات الجوهرية مجمّعة في `OWNER_DECISIONS.md`.

## 3. الرؤية العامة للمنصة

المنصة تهدف إلى مساعدة الأسرة على تحويل القيم من مفاهيم نظرية إلى ممارسات سلوكية
عملية داخل البيت. ولي الأمر لا يدخل المنصة لقراءة محتوى تربوي فقط، بل يدخل ليقوم
بخطوات عملية:

1. إنشاء حساب أسري
2. إضافة الأبناء
3. اختيار قيمة من القيم الرئيسية الأربع
4. اختيار هدف جاهز أو إنشاء هدف مخصص
5. تحويل الهدف إلى مهام عملية
6. متابعة تنفيذ المهام
7. اعتماد الإنجاز أو مراجعته
8. تحفيز الابن عبر XP، مستويات، إنجازات، وصناديق مكافآت
9. الاطلاع على تقارير تبيّن مدى التقدم والأثر السلوكي

## 4. النموذج الجوهري

```
القيمة → الهدف → المهمة → الممارسة → المتابعة → الأثر
```

التلعيب ليس هو جوهر المنصة، بل طبقة تحفيزية فوق جوهر تربوي وسلوكي.

## 5. الفئة المستهدفة

- **المستخدم الأساسي:** ولي الأمر.
- **المستخدمون الثانويون:** الأبناء داخل الأسرة.

نطاقات عمرية مشار إليها (غير محسومة):
- من 3 حتى 15 سنة (البرنامج التربوي).
- من 5 حتى 21 سنة (تصور المنصة الرقمية).

**لا يجوز تثبيت الفئة العمرية النهائية افتراضيًا في الكود.** يُصمَّم النظام بحيث يدعم
مراحل عمرية قابلة للتهيئة من لوحة الإدارة بدلًا من كتابة الأعمار Hard-coded.

المراحل العمرية المعتمدة (3 مراحل — علم اجتماع الطفولة):
- 3–6: الطفولة المبكرة
- 7–12: الطفولة المتوسطة
- 13–18: المراهقة

## 6. القاعدة النهائية للعمل

لا تبدأ البرمجة من XP أو صناديق المكافآت أو الواجهات الجذابة. ابدأ من النموذج الصحيح:

```
القيم الأربع → الأهداف → المهام → التنفيذ → الاعتماد → القياس → التلعيب → التقارير
```

أي تنفيذ يخالف هذا الترتيب سيؤدي إلى منصة جميلة شكليًا لكنها ضعيفة تربويًا ومنتجيًا.
