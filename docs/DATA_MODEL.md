# نموذج البيانات — DATA_MODEL

> هذا مخطط **أولي قابل للتعديل**. لا تُعتبر هذه الجداول نهائية قبل بناء Data Model
> تفصيلي معتمد. المصدر التنفيذي هو `supabase/migrations/`.

## نظرة عامة

نموذج البيانات يعكس النموذج الجوهري:
`القيمة → الهدف → المهمة → التنفيذ → الاعتماد → القياس → التلعيب → التقارير`

## الجداول

### الهوية والأسرة
| الجدول | الوصف |
|--------|-------|
| `users` | حسابات المصادقة (ولي الأمر، مدير المحتوى، مدير النظام). مرتبط بـ `auth.users`. |
| `families` | ملف الأسرة. مالكها مستخدم (ولي أمر). |
| `family_members` | ربط المستخدمين بالأسرة وأدوارهم داخلها. |
| `children` | ملف الابن/الابنة (لا يملك حساب مصادقة — دخول تابع). |
| `age_stages` | المراحل العمرية القابلة للتهيئة (بدل الأعمار Hard-coded). |

### القيم والأهداف والمهام
| الجدول | الوصف |
|--------|-------|
| `core_values` | القيم الرئيسية الأربع. |
| `sub_values` | القيم الفرعية المرتبطة بكل قيمة. |
| `goal_templates` | الأهداف الجاهزة (مكتبة المحتوى). |
| `goals` | الأهداف الفعلية (جاهزة معتمدة أو خاصة) المرتبطة بأسرة/ابن. |
| `task_templates` | المهام الجاهزة (مكتبة المحتوى). |
| `tasks` | تعريف المهمة الفعلية المرتبطة بهدف. |
| `assigned_tasks` | إسناد مهمة لابن محدد (مع التواريخ والحالة). |

### التنفيذ والاعتماد
| الجدول | الوصف |
|--------|-------|
| `task_completions` | محاولات إكمال المهمة من الابن (مع الإثبات). |
| `guardian_reviews` | مراجعة ولي الأمر (اعتماد/رفض/إعادة/XP إضافي/تشجيع). |

### التلعيب
| الجدول | الوصف |
|--------|-------|
| `xp_events` | **سجل أحداث XP** (وليس رقمًا إجماليًا) مع السبب. |
| `levels` | تعريف المستويات الرمزية وعتبات XP. |
| `badges` | تعريف الشارات وشروطها. |
| `child_badges` | الشارات الممنوحة لكل ابن. |
| `reward_boxes` | تعريف صناديق المكافآت وشروط فتحها. |
| `reward_box_items` | محتوى الصناديق الممكن. |
| `reward_box_openings` | سجل فتح الصناديق. |
| `achievements` | تعريف الإنجازات. |
| `child_achievements` | الإنجازات المحققة لكل ابن. |
| `family_challenges` | التحديات العائلية. |

### التقارير والحوكمة
| الجدول | الوصف |
|--------|-------|
| `reports` | تقارير مولّدة/مخزّنة (ابن، أسرة، إداري). |
| `consent_logs` | سجل الموافقات (خصوصية، صور، تلعيب). |
| `audit_logs` | سجل العمليات الحساسة (حذف بيانات، تغييرات صلاحيات). |

## العلاقات الرئيسية

```
users (1) ──< family_members >── (1) families
families (1) ──< children
children (1) ──< assigned_tasks >── (1) tasks ──< (1) goals
goals (n) ── (1) core_values ── (1) sub_values
goals (n) ── (0..1) goal_templates
tasks (n) ── (0..1) task_templates
assigned_tasks (1) ──< task_completions ──< guardian_reviews
children (1) ──< xp_events
children (1) ──< child_badges >── badges
children (1) ──< child_achievements >── achievements
children (1) ──< reward_box_openings >── reward_boxes ──< reward_box_items
core_values, goal_templates, task_templates ── age_stages
```

## مبادئ التصميم في المخطط

- **XP كسجل أحداث:** الإجمالي يُحسب من `xp_events` (يمكن تخزين Materialized total لاحقًا).
- **مراحل عمرية قابلة للتهيئة:** `age_stages` بدل أعمار ثابتة في الكود.
- **الابن بلا مصادقة:** `children` منفصل عن `users`/`auth.users`.
- **الخصوصية:** RLS على كل جداول الأسرة؛ التقارير العامة من Aggregations مجهولة الهوية.
- **حق الحذف:** حذف الأسرة/الابن Cascade مع تسجيل في `audit_logs`.
- **القيم قابلة للتوسعة:** `core_values` جدول (وإن عرضت الواجهة الأربع فقط في MVP).
